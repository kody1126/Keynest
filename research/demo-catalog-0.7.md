# Keynest 0.7 演示目录

全新演示库包含 **34 条虚构密钥、10 个工具组**。公开测试密码仍为 `Keynest-Demo-2026`；全部样例保持 `demo-only-not-a-real-key-NNN` 格式、额度适配器 `.none` 和空额度快照。

原 24 条记录的 ID、名称、秘密值、提供商、网址、时间、标签与备注保持不变。只给完全未改动的 3 条旧模型样例追加新工具关联：OpenAI → n8n，Claude → OpenClaw / LangGraph，OpenRouter → Cline。用户修改过任何字段的记录不会被补关联，删除的记录不会恢复。

## 新工具与样例

新增工具的 ID 尾号依次为 7–10，并保存对应 `templateID`：

| 工具 | 模板 ID | 组合示例 |
| --- | --- | --- |
| Cline 编程助手 | `cline` | OpenRouter 模型、Context7 文档、GitHub 仓库 |
| OpenClaw 个人 Agent | `openclaw` | Claude 模型、浏览器、长期记忆、联网研究 |
| n8n 内容自动化 | `n8n` | OpenAI 模型、网页采集、Notion 笔记 |
| LangGraph 知识 Agent | `langgraph` | Claude 模型、工具连接、记忆、追踪、向量检索 |

工具仅展示凭据组织方式，没有安装对应软件或部署工作流。新凭据的 ID 尾号依次为 25–34：

| 提供商 | 示例用途 | 收藏分类 |
| --- | --- | --- |
| Context7 | 文档检索 | Skill 与插件 |
| Browserbase | 托管浏览器 | 开发服务 |
| Apify | 网页采集 | Skill 与插件 |
| Composio | 工具连接 | 开发服务 |
| Mem0 | 长期记忆，供两个 Agent 复用 | 开发服务 |
| LangSmith | Agent 追踪 | 开发服务 |
| Qdrant | 向量检索 | 开发服务 |
| Perplexity | 联网研究 | Skill 与插件 |
| Notion | 笔记整理 | Skill 与插件 |
| GitHub | 仓库能力 | Skill 与插件 |

Base URL 与官网来自离线提供商目录。Qdrant 保持空 Base URL，因为真实地址取决于用户集群；Browserbase 等额外项目标识按提供商填写提示处理，不生成可用账户或凭据。历史 0.6 的默认字段已冻结，今后修改预设默认值不会改变旧样例的原样识别。

## 版本与用户修改保护

`DemoVault.catalogRevision == 7` 独立于加密文档 payload 版本 3：

- 从目录版本 6 升级时，只添加本次 10 条记录和 4 个工具，并对完全匹配旧样例的模型记录补关联。
- 从目录版本 5 升级时，先补 0.6 的新 ID，再补 0.7；被删掉的 0.5 旧样例和工具不重建。
- 从目录版本 4 升级时，先执行冻结的 0.4 → 0.5 迁移。原来的完整字段匹配与用户修改保护继续有效。
- 现有同 ID 工具或密钥完整保留。只有新工具与样例完全匹配，新增条目和旧模型才可关联到它，防止把凭据接到用户自定义的冲突工具上。
- 目录版本 7 或更高不再增补；用户升级后删除的新样例不会在下次解锁时重新出现。
- 重复传入旧目录版本不会产生重复记录或重复关联。App 仍必须在成功写入加密文档后保存版本标记，才能保留升级后删除新样例的意图。

App 应以保存的目录修订号和源 payload 版本区分旧库。不能把 `requiresUpgrade` 等同于目录版本 4，因为 0.6 的 payload 2 升至 3 也属于格式升级。

测试覆盖 34 条无效凭据、禁用额度请求、品牌模板引用、Skill / Agent 类别、原样模型复用、每个字段的用户修改、删除记录与工具、同 ID 冲突、目录 5 / 6 / 7 路径、迁移幂等和无 `templateID` 的旧 payload 2。最终执行结果统一见 [验证记录](../macos/verification.md)。
