# Keynest 0.5 产品方向与取舍

记录日期：2026-09-23。本文整理本次对话形成的产品方向与已落地边界，不把讨论中的想法当作已实现功能。运行与安全细节见 [macOS 使用说明](../macos/README.md)，验证结果以 [验证记录](../macos/verification.md) 为准。

## 要解决的问题

用户最初希望有一个本地工具，收集模型、Skills、插件和其他服务的 API 与密钥，保存来源，并尽可能查看额度。随着实际使用场景展开，需要管理的不只是平台名单：一个工具可能同时需要搜索、推理、生成等多种 API；同一平台还可能有个人与团队账号，以及正式、开发、测试等环境。

0.5 因此把主要入口放在「我的工具」。用户先找到正在使用的工具，再找到它需要的密钥和 API 地址，直接复制到使用处。平台预设帮助录入来源，账号与环境帮助分辨用途。Keynest 不自动修改这些工具的配置，也不充当模型调用网关。

## 工具与密钥分开保存

| 对象 | 表达什么 | 当前规则 |
| --- | --- | --- |
| 工具 `ToolGroup` | 使用一组 API 的工作对象，例如研究助手、内容工作台 | 最多 100 个；名称、备注和独立身份 |
| 密钥 `SecretEntry` | 一把凭据及其平台、来源、账号、环境 | 最多 2000 把；密钥仍是一条独立记录 |
| 工具关联 | 哪些工具使用这把密钥 | 一工具可有多密钥，一密钥最多关联 20 个工具 |
| 账号与环境 | 同平台凭据的用途区别 | 自由填写账号标记和环境，并支持环境筛选 |

关联同一条密钥，比为每个工具复制一份凭据更容易维护。用户更换密钥或地址后，所有关联工具看到的是同一条更新记录。这里的共享仅指本机工具之间的引用，不是多人分享密码库。

工具分组与密钥有不同的删除含义：移除工具只删除分组及关联，保留密钥；删除密钥会让所有工具失去这条本机记录，不会撤销远端平台上的凭据。没有关联工具的密钥统一进入「未归组」，可以稍后整理。

## 优先完成的日常流程

1. 新建工具，填写名字及用途。
2. 在工具内关联已有密钥，或新建密钥并自动归入当前工具。
3. 使用平台、账号和环境区分多把密钥，必要时按环境筛选。
4. 从列表或详情直接复制密钥；从详情或菜单复制 API 地址。

侧栏同时保留全部密钥、常用密钥、未归组和用途分类，避免必须先建工具才能保存内容。搜索覆盖密钥名称、平台、关联工具、账号、环境、标签、备注和网址，不读取密钥明文作为搜索字段。

密钥默认隐藏，显示后 20 秒自动收起。密钥与 API 地址的复制共用 30 秒清除机制，只清除仍属于本次复制的剪贴板内容。10 分钟无操作后锁定密钥库。系统剪贴板历史等外部软件仍不在应用控制范围内。

## 平台预设与官网入口

12 个平台统一展示、按名称和别名搜索，不以国家分类。预设填写默认名称、提供商、官网与 API 地址；任意自定义平台仍可保存。

编辑和详情里的「API 官网」链接用于主动访问官方 API 网站，API 地址用于接口配置，来源网站用于保留用户原有申请页、控制台或自建服务信息。三个概念不混为一项，新增官网入口也不覆盖旧的自定义来源。

平台图标来自随 App 打包的本地资源。选择预设不会检查凭据、抓取图标、自动开启额度查询或向多个平台尝试发送密钥。切换到不同预设时保留用户密钥和自定义信息，并关闭旧额度设置、清除旧快照。

## 本地安全与旧数据升级

正式库继续使用整库 AES-256-GCM 加密；工具、关联、账号与环境与密钥一起加密。主密码由用户设置，应用不保存该密码。数据不主动云同步，不自动扫描其他软件的凭据。

0.5 读取旧版数据载荷 1，并在后续保存时写入载荷 2。第一次新格式写入之前，先保存原始密文为同目录的 `vault-before-0.5.keynest`。备份保留当时的密码，保存失败则不继续升级写入。0.4 不能读取新载荷；回退需要旧备份，不能把新工具关系带回旧版。

备份合并同时处理工具、密钥及引用关系。内容冲突保留为不同版本，完全相同的内容不重复添加；再次导入同一备份不会持续制造副本。这使导入用于恢复与汇合，而不会默默覆盖已有记录。

## 用演示库验证产品流程

独立 `Keynest Demo.app` 使用公开密码 `Keynest-Demo-2026`，没有用户名，与正式 App 的 bundle ID 和数据目录分开。新库提供 9 把无效虚构密钥、3 个工具，用于体验多平台、多账号、多环境和共享关联。

旧演示库仅在旧载荷升级时增补新样例；用户改过的旧条目不覆盖，删除过的旧样例不复活。公开演示密码不适合真实凭据。演示版在模型层禁用额度请求、备份导入导出和改密码，但允许用户手动打开官网链接，因此不称为完全离线模式。

## 本轮明确的取舍

- **先完成本地整理与取用。** 不自动改写 CLI、MCP、Skill 或模型客户端的配置，减少应用替用户决定凭据用途的情况。
- **额度作为可选信息。** 正式版只支持 DeepSeek、硅基流动和 OpenRouter 的手动官方接口查询；没有全平台实时同步。OpenRouter 显示当前 Key 限额及用量，不是账户总余额。
- **Touch ID 留待后续。** 本轮只讨论了需求，尚未实现 Touch ID 或系统钥匙串自动解锁。
- **保持原生 Mac 交互。** 使用系统控件、三栏导航和清晰焦点，核心操作不依赖网页或外部 UI 资源。
- **图标可继续迭代。** 当前选择 C2「冰蓝通透」，保留 A–H 与 C1–C4 共 12 个方案及重建资源。
- **安装入口统一。** 中间 App 放入 `dist/apps.noindex/`，正式运行位置固定为 `~/Applications`。替换旧 App 前验证并压缩备份，不通过重置系统索引或清理系统数据库处理重复入口。

后续功能应围绕能否更快找到正确工具、正确账号和正确环境的凭据来取舍。任何自动联网、配置写入或解锁能力，都需要明确其数据边界及用户主动触发的入口。
