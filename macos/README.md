# Keynest for macOS

当前版本 **0.8.1** 完成一轮错误与安全边界修复，见 [检查报告](../research/security-review-0.8.1.md)。

Keynest 0.8 增加日常取用的首页：解锁后按平台找到密钥，每把单独复制；选平台、粘贴密钥即可快速保存。原有三栏管理页、61 个平台预设、25 个 Skill / Agent 工具模板和 Touch ID 解锁继续保留，一个工具可使用多把密钥，一把密钥也可供多个工具使用。应用采用原生 SwiftUI / AppKit、系统字体、SF Symbols 和原生编辑窗口。首页说明见 [0.8 首页与快速添加](../research/home-usability-0.8.md)，早期设计取舍见 [macOS 设计参考](../research/macos-design-references.md)及 [0.5 产品方向](../research/product-direction-0.5.md)。当前暂定 C2「冰蓝通透」钥匙扣图标，以静态 ICNS 构建；全部 12 个样式保留在 [图标样式库](Resources/design/README.md)，[图标设计记录](../research/keynest-icon-design.md)包含设计依据。

当前交付面向 **macOS 14+、Apple Silicon（arm64）**，不依赖 Node.js、浏览器、云端账户或第三方 Swift Package。源码按构建机器的架构编译，也可在 Intel Mac 上构建；本次未提供或验证 Intel 安装包。

## 安装与首次使用

本机正式应用位置为 `~/Applications/Keynest.app`，独立演示版为 `~/Applications/Keynest Demo.app`。打包后的分发文件位于 `macos/dist/Keynest-0.8.1-arm64.dmg`，同时包含两个 App；统一安装到 `~/Applications` 后打开，不从 DMG 或构建目录运行。

应用启用 **Hardened Runtime**，采用 **ad-hoc 本地签名**，未使用 Apple Developer ID 签名，也未经过 Apple 公证。这适合本机实验构建，不等于经 Apple 认证的分发版本。

正式版首次打开时创建主密码：

1. 输入 12–1024 个字符、UTF-8 最多 16 KiB 的主密码，并再次确认。已有旧密码的解锁规则保持兼容。
2. 点击「创建密钥库」。主密码没有找回入口，请自行妥善保存。
3. 在首页选择平台，粘贴密钥，点击「保存到首页」。预设会填写默认名称和 API 地址；项目专属地址按提示自行填写。
4. 需要区分账号或环境时，展开「账号、环境与地址（可选）」。需要标签、备注、工具关联等信息时，点击「完整编辑…」继续填写当前草稿。

以后解锁默认进入首页。首页可添加其他平台，也可以从工具模板开始，为一个工具关联多把密钥。

默认数据位置为：

```text
~/Library/Application Support/Keynest/
├── vault.keynest     加密密钥库
└── instance.lock     单实例文件锁
```

关闭或删除应用不会自动删除此数据目录。原生版本不会读取项目根目录的 Web `.data/vault.json`，也不会扫描其他应用的密钥文件。

## 独立演示版

打开 `Keynest Demo.app`，使用公开测试密码 **`Keynest-Demo-2026`** 解锁，**没有用户名**。这是 Keynest 自己的本地测试库，不会注册或提供任何真实模型 API 账户。

首次启动且演示库不存在时，会自动创建 **34 把虚构密钥和 10 个工具**。样例覆盖大模型、搜索抓取、图像、语音、地图天气、开发、邮件，以及 Agent 浏览器、记忆、知识库和追踪服务，并展示同平台多个账号、正式/开发/测试环境，以及共享密钥。所有样例密钥均以 `demo-only-not-a-real-key-` 开头，不能调用真实 API。

旧演示库按独立目录修订号增补新样例，只有加密保存成功后才记录完成。用户修改过的条目保持原样，已经删除的旧样例不重新创建；完成升级后也不会每次启动都重新填充。0.8 的演示目录修订号仍为 7，不因首页更新增加或重填样例，测试密码不变。旧载荷版本 1 仍先按 0.5 规则迁移，正式库不填充演示数据。

| 项目 | 正式版 | 演示版 |
| --- | --- | --- |
| App | `Keynest.app` | `Keynest Demo.app` |
| 密码 | 用户自行设置 | 公开的 `Keynest-Demo-2026` |
| 数据目录 | `~/Library/Application Support/Keynest/` | `~/Library/Application Support/Keynest Demo/` |
| 工具与密钥的添加、编辑、关联、搜索、显示、复制 | 可用 | 可用，仅放虚构凭据 |
| 额度查询 | 手动选择并刷新 | 模型层禁用，不发送额度请求 |
| 备份导入、导出、改密码 | 可用 | 模型层禁用 |

演示 App 使用独立的 bundle ID 与数据目录，忽略 `--test-data-directory` 启动参数，避免演示数据被这个参数引到正式库。初始化只在自己的库不存在时写入样例，不会覆盖正式数据。

**演示密码公开，即使文件经过加密也不适合存放真实凭据。** 演示界面有常驻提醒。官网及自定义来源链接仍可手动交给默认浏览器打开；它不调用模型 API，但不是完全离线模式。

## 首页日常使用

解锁后默认显示首页。已保存的密钥按平台组成卡片，每张卡片直接显示最多 2 把；每行都有自己的「复制」按钮，复制成功后显示「已复制」。同平台超过 2 把时，点击「查看全部」打开可滚动的密钥列表，再明确选择需要的那一把。

卡片显示密钥名称、账号、环境和 API 主机名，方便区分个人与团队账号、开发与正式环境，以及不同网关。每行更多菜单可复制 API 地址、设置常用、查看详情或编辑；地址为空时不能复制。卡片底部可添加同平台密钥，匹配到预设的平台另有「API 官网」入口。

使用「全部 / 模型 / Skill 与服务 / 常用」分段筛选首页。首页搜索平台名称及别名、密钥名称、账号、环境、标签和关联工具名称，**不读取密钥字段、网址、备注或额度数据**。先按搜索和分段筛选匹配条目，再按平台分组，所以同平台的不匹配密钥不会一并显示。

从首页选择平台后进入快速添加窗口，主要只需粘贴密钥。名称、账号、环境和 API 地址位于可选展开区；已有同平台密钥时，这一区域会自动展开，并给新密钥生成不与现有名称重复的编号默认名，例如「ChatGPT / OpenAI · 2」。可以改成自己的用途名称。「完整编辑…」保留当前草稿，继续填写标签、备注或工具关联。自定义平台使用完整编辑窗口。

首页不自动选中任何密钥。需要详细管理时使用「查看详情」或 `⌘2` 进入管理页；复制和编辑所选记录的快捷键仅在管理页选中记录后可用。

## 工具与多把密钥

首页之外，管理页保留「全部密钥」「常用密钥」「未归组」「我的工具」和分类。分类仍包含 AI 模型、Skill 与插件、开发服务、其他；提供商是任意文本，可以填写平台、插件或自建服务名称。

工具表示实际使用 API 的工作对象，例如「研究助手」需要搜索、推理和长文处理的多把密钥。先创建工具，再使用「关联已有密钥」整理已有记录，或在工具内直接新建密钥；新建条目会自动关联当前工具。

同一把密钥可以关联多个工具，所有工具引用同一条记录，编辑一次即可更新。移除工具分组只清除它的关联，密钥仍保留在「全部密钥」；没有任何工具关联的条目进入「未归组」。删除密钥则会从所有关联工具中移除这条本机记录，但不会撤销服务商上的真实密钥。

最多可创建 100 个工具；工具名称最多 80 字符、备注最多 1000 字符，每把密钥最多关联 20 个工具。

## 密钥信息、搜索与复制

每项收藏可记录：

| 字段 | 用途 |
| --- | --- |
| 名称、密钥 | 必填；名称最多 120 字符，单行密钥最多 8192 字符 |
| 分类、提供商 | 用途归类和服务来源；不要求选择预设模型平台 |
| 关联工具 | 同一条密钥可供多个工具使用，最多关联 20 个 |
| 账号标记、环境 | 区分个人/团队账号及正式/开发/测试用途；分别最多 120 和 40 字符，均可自定义 |
| 来源网站 | 用户保存的官网、申请页面或控制台地址；点击后在默认浏览器打开 |
| API 地址 | 可选的接口地址，与来源网站分开保存 |
| 标签、备注 | 项目、环境、使用工具及其他上下文；最多 12 个标签，每个 40 字符，备注 4000 字符 |
| 常用 | 使用星标将密钥加入「常用密钥」 |

网址需是完整的 HTTP 或 HTTPS 地址，不能带用户名、密码、查询参数或片段。它们不会被应用自动访问，也不用于自动抓取网站图标。

匹配到预设服务商时，详情与编辑窗口都有独立的「API 官网」链接，指向预设提供的官方 API 网站。这与 API 请求地址分开，且不会改写旧收藏已经保存的自定义来源网站。

管理页的工具栏搜索保留原有范围：密钥名称、平台、关联工具名称、账号、环境、标签、备注、来源网站与 API 地址，不读取密钥字段。搜索作用于当前侧栏范围，环境筛选可进一步缩小结果；也可清除筛选或切换全部密钥。首页搜索范围更窄，排除网址和备注，并支持平台别名。

列表与详情都可以一键复制密钥，无需先显示明文。详情、列表右键菜单和应用的「密钥」菜单可复制 API 地址；未填写地址时不可复制。

| 快捷键 | 操作 |
| --- | --- |
| `⌘1` | 显示首页 |
| `⌘2` | 管理全部密钥 |
| `⌘F` | 切换到首页并聚焦搜索，同时切回「全部」分段 |
| `⌘N` | 添加密钥 |
| `⇧⌘N` | 添加工具 |
| `⇧⌘C` | 复制管理页选中收藏的密钥；首页没有默认选中记录 |
| `⌘E` | 编辑管理页选中收藏 |
| `⇧⌘L` | 锁定密钥库 |

密钥显示后 **20 秒**自动隐藏，切换条目、打开编辑窗口或窗口失焦时也会隐藏。复制密钥或 API 地址后，会在 **30 秒**后清除本次复制内容；应用会核对剪贴板变化，避免擦除期间新复制的内容。锁定时也会尝试清除仍属于本次复制的内容。第三方剪贴板历史不受这个清除动作保证。

密钥库在 **10 分钟无操作**后锁定；系统休眠或当前系统用户会话退出活动状态时也会锁定。额度请求不会替用户延长解锁时间。

删除收藏只删除本机记录，不会撤销服务商上的密钥。需要停用密钥时，请到对应服务商处理。

## 工具、Skill 与 Agent 模板

点击侧栏「添加工具」，按客户端、Agent 与工作流、Skill 浏览 25 个离线模板。15 个真实产品附本地品牌图标，10 个功能组合展示对应 API 服务的图标。没有合适选项时仍可添加自定义工具。

选择模板后会填入工具名称，并显示所需凭据用途。每个用途可选择服务商，复用当前库中相同平台的已有密钥，或保存一把新密钥；同一平台有多把密钥时需要明确选择。API 官网和默认接口地址来自平台预设，项目专属地址保留为空。可选用途默认关闭。

「添加工具」会将工具和所有选中的凭据关联一次性写入加密库；任意字段无效时全部不保存。当前窗口内返回模板、切换平台后再切回会恢复各自草稿；取消表单无改动，锁定时关闭表单并释放草稿。复用密钥保留原条目、账号、环境、备注和其他工具关系，只新增关联，不复制密钥实体。

模板用途是整理凭据。模型、工作流和具体调用仍在对应工具中配置；OAuth 或订阅登录不需要虚构 API Key。完整目录与官方依据见 [模板记录](../research/skill-agent-templates-0.7.md)。

## 服务商预设

首页展示常用平台入口，「全部 61 个平台」打开完整服务商选择器。选择器按模型与推理、图像与语音、搜索与采集、开发与数据、消息与协作、Agent 工具分组，不按国家分类；搜索支持平台名称、常用别名与用途。也可以选择自定义服务。首页选择平台后进入快速添加，管理页仍可使用完整编辑表单。预设用于减少录入，不会切换其他工具的提供商配置。

除原有 OpenAI、Claude、Gemini、DeepSeek、Qwen、Kimi 等模型平台外，还包括推理服务、图像和语音服务、搜索与抓取、GitHub 等开发服务，以及消息与邮件 API。完整清单、具体用途和逐项官方来源见 [API 预设目录](../research/api-catalog-0.7.md)。

选择预设后会填写默认名称、提供商、来源网站和 API 地址；项目专属 URL 不猜测，留空并给出填写提示。61 个服务均附有真实品牌图标，另有 15 个工具品牌图标，随应用打包；原有 12 个图标文件保持不变。打开选择器和选择预设都不需要联网，不访问官网抓取图标。首页卡片、快速添加和编辑窗口的「API 官网」是独立链接，点击后才会在浏览器打开。

全新空白草稿仍使用默认分类时，首次选择预设会建议「AI 模型」「Skill 与插件」或「开发服务」。已有内容、自选的其他分类以及之后的预设切换均保留原分类，旧收藏不会批量重新归类。

在编辑表单点击「选择预设…」可以重新选择：

- 密钥、备注、标签、分类、星标和收藏身份保留。
- 已自定义的名称、来源网站和 API 地址保留；只有空字段或仍等于上一预设默认值的字段会更新。
- 从表单返回选择器后取消，会返回原草稿；表单内取消则放弃本次编辑。
- 切换到不同预设时，额度查询回到「不启用」，旧额度快照清除。再次选择当前预设会保留已经手动选择的额度设置。

预设不会验证密钥、登录账户或发送额度请求。需要额度查询时，仍须明确设置并手动刷新。OpenAI API 密钥与 ChatGPT 订阅分开管理。

## Touch ID 解锁

在支持 Touch ID 和 Secure Enclave、且已录入指纹的 Mac 上，首次设置或输入主密码解锁时勾选启用，也可解锁后在设置中切换「使用 Touch ID 解锁」。下一次启动并激活 App 时自动请求一次系统指纹验证；取消后可重试或改用主密码，手动锁定不会立刻自动解锁。

系统验证约束直接作用在 Secure Enclave 私钥运算上。每次使用新的认证上下文，不复用上次指纹批准，不把主密码或未加密的解锁密钥写入文件。`biometric-unlock.keynestlocal` 只保存硬件绑定的私钥表示和 AES-GCM 加密的解锁资料，权限 0600，绑定当前密钥库路径；它不包含在 `.keynest` 导出备份中。

关闭 Touch ID 会删除本机解锁资料。修改主密码会先撤销旧指纹解锁资料，再写入新密码加密的库；之后可重新启用。更换指纹集合、迁移设备或恢复不同密钥库后，应使用主密码并重新启用。没有指纹传感器、指纹暂时不可用或取消验证时，主密码仍可解锁。

正式库和演示库分别启用。当前本地 ad-hoc 签名无法使用需要授权 entitlement 的 Data Protection Keychain，因此使用 Apple 支持的非持久 Secure Enclave 私钥与硬件绑定表示；不创建签名证书，也不降级为仅检查弹窗结果的解锁。实现依据和验证边界见 [Touch ID 记录](../research/touch-id-0.6.md)。

## 加密备份与合并导入

在正式版工具栏的密钥库菜单中选择「导出加密备份…」，通过系统保存窗口选择文件位置。备份是加密的 `.keynest` 文件，使用导出时的主密码才能读取。演示版不提供导入或导出。

导入支持两种场景：

- **新密钥库**：首次设置页选择「从加密备份恢复…」，选中备份并输入其原主密码。恢复后继续使用这个密码。
- **已有密钥库**：先解锁，再选择「导入加密备份…」，输入备份本身的密码。条目合并到当前库，当前库的主密码保持不变。

合并同时处理工具、密钥与它们之间的关联。完整内容相同的记录跳过；同一 ID 下内容不同的记录保留为独立版本，导入密钥的工具关联也会映射到对应版本，不覆盖已有内容。再次导入同一份备份不会反复产生相同副本。后来修改过的收藏可能以两项并存，供用户自行整理。

可在密钥库菜单中更改主密码。**已经导出的旧备份仍需旧密码**；更改密码后建议重新导出备份。单个加密库文件上限为 4 MiB，最多 2000 把密钥、100 个工具。

Web 0.1 实验使用另一种加密格式；其 `vault.json` 不能作为原生 `.keynest` 备份导入。原生 App 不会自动迁移或改写 Web 数据。

## 升级与兼容性

0.8 沿用数据载荷版本 3 和演示目录修订号 7，首页及搜索调整不改变存储格式。以下为 0.7 引入、在 0.8 继续适用的迁移规则。

0.7 的载荷版本 3 新增可选的工具模板标识，以便保留工具图标。当前版本可读取旧版 1 / 2，保留密钥、来源、备注、关联、账号、环境和工具。自定义工具没有模板标识时继续正常使用；未知模板标识保留，显示通用图标。

第一次保存旧格式前，先在同一密钥库目录写入原始密文备份 `vault-before-0.7.keynest`。备份保留原密码，之后更改主密码不会改变备份。已有备份和更早的 `vault-before-0.5.keynest` 都不会覆盖。备份失败时不继续保存新格式；演示库使用自己目录中的备份。

0.6 及更早版本无法读取新版写出的版本 3，回退需要升级前的备份。加密外层仍为版本 1，AES-256-GCM 与密钥派生方式保持不变，Touch ID 的解锁资料仍适用于同一个库。

## 手动额度查询

正式版默认只收藏密钥；选择服务商预设也不会自动开启查询。需要查询额度时，在编辑窗口展开「高级选项」，选择额度服务，再到详情展开「额度查询」并点击刷新。演示版在模型层禁止此请求，保存条目时也会关闭额度设置。

| 额度服务 | 固定官方地址 | 展示含义 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/user/balance` | 账户总余额、赠送及充值余额；币种分别显示 |
| 硅基流动 | `https://api.siliconflow.cn/v1/user/info` | 中国站账户总余额；不保存返回的个人资料 |
| OpenRouter | `https://openrouter.ai/api/v1/key` | 当前 Key 的消费限额、剩余额度与累计/日/周/月用量 |

这是三个官方接口的**手动快照查询**，不是所有模型、订阅或账户的实时同步。OpenRouter 未设置 Key 限额，不代表账户无限余额；该接口不返回账户总余额。多个密钥可能共享账户余额，不能据此把各条目相加。

查询前会核对密钥格式；如果填写了 API 地址，还会检查它与选定额度服务的 HTTPS 域名和端口是否一致。不匹配时不会发送密钥。应用不试探其他平台，不发送推理请求来验证密钥，也不读取浏览器登录状态或 Cookie。

请求使用临时 URLSession，不持久化 Cookie、URL 缓存或认证凭据；拒绝重定向，设置 10 秒超时与 1 MiB 响应上限。网络或格式错误不会替换上一次成功快照。改变密钥、API 地址或额度服务后，旧快照会清除。

## 安全边界

| 当前机制 | 作用与边界 |
| --- | --- |
| 整库 AES-256-GCM | 通过 CryptoKit 加密工具、关联、名称、密钥、账号、环境、备注、标签和额度快照；格式及 KDF 参数纳入认证 |
| PBKDF2-HMAC-SHA256 | CommonCrypto 实现，600,000 次迭代、32 字节随机 salt，派生 256 位密钥；抵抗离线猜测仍依赖主密码强度 |
| 随机数 | 使用系统安全随机源生成 salt 和每次写入的 nonce |
| 本机文件保护 | 数据目录 0700、库文件 0600、原子写入和单实例锁；拒绝符号链接及硬链接库文件；单实例锁先核验普通文件、链接数及所有者，不生成明文备份 |
| 剪贴板 | 本次复制使用 currentHostOnly 禁用跨设备接力，附敏感/临时标记；30 秒或锁定时只清除本 App 仍拥有的内容，不能强制其他剪贴板软件遵守标记 |
| Hardened Runtime | 两个 App 均启用，没有添加放宽运行时保护的 entitlement；不等于 App Sandbox、Developer ID 签名或 Apple 公证 |
| 解锁与锁定 | 解锁后为展示及查询在进程内保留数据；锁定清除应用持有的会话和条目引用，不能保证 Swift 字符串、系统缓存或所有内存副本物理清零 |
| 出站连接 | 正式版主动额度查询访问固定官方接口；两个 App 都允许用户点击官网或来源链接交给默认浏览器 |
| 无主动云同步 | 应用不上传密钥库；用户自己的系统备份或同步软件仍可能备份密文 |

原生版本没有本地 HTTP 服务、远程脚本、遥测或外部 UI 资源。Touch ID 为本机可选功能，不提供多人共享库或云同步。多个工具关联同一密钥是本机数据组织，不代表向其他用户共享凭据。

项目没有使用 MD5。原子替换后如果目录同步失败，界面提示备份并保持内存与已写入密文一致，不再把已经提交的修改当作未保存。自动锁定按单调时钟计算，系统时间回拨不会延长会话。

取消备份导入会使尚未提交的异步解密结果失效；更换主密码提交期间不能关闭窗口。旧库里此前接受的异常 URL 元数据仍可读取并编辑，新输入会拒绝控制字符和无效端口；地址不合法时禁止复制 API 地址或打开自定义网站。

该实验版尚未经过独立安全审计，也不具备 App Sandbox 隔离。加密主要保护未解锁的磁盘文件，不能防止已经控制当前用户会话的恶意软件、解锁时内存读取、截屏或剪贴板监听。ad-hoc 签名与 Apple 公证是不同的机制，不能当作独立安全评估。

## 从源码构建

需要 macOS 14+ 和可用的 Swift 5.9 以上 Apple Command Line Tools 工具链；无需安装完整 Xcode。项目使用系统 SwiftUI、AppKit、CryptoKit、CommonCrypto 与 Security，不需要下载第三方 Swift 包。检查脚本使用本机 Python 3 发现测试方法，打包使用系统 `codesign`、`iconutil` 和 `hdiutil`。

在本目录执行：

```sh
bash scripts/run-checks.sh
bash scripts/run-app-checks.sh
zsh scripts/build-app.sh
zsh scripts/build-demo-app.sh
zsh scripts/package-app.sh
zsh scripts/install-apps.sh
```

`build-app.sh` 构建 release 可执行文件、按 `Resources/AppIcon.selection` 编译所选图标、组装应用并进行启用 Hardened Runtime 的 ad-hoc 签名。输出为：

```text
macos/dist/apps.noindex/Keynest.app
```

`build-demo-app.sh` 复制已构建的正式 App，设置独立的 `local.keynest.demo` 标识和显示名称，再进行 ad-hoc 签名与验证。它输出 `macos/dist/apps.noindex/Keynest Demo.app`，不启动应用，也不创建或改写任何密钥库。

`package-app.sh` 会先调用上述两个构建脚本，将正式 App 和 Demo App 一起放入与本机架构匹配的 DMG，使用 `hdiutil verify` 校验，并生成 `.sha256` 校验文件。Apple Silicon 上的产物为：

```text
macos/dist/Keynest-0.8.1-arm64.dmg
macos/dist/Keynest-0.8.1-arm64.dmg.sha256
```

中间 App 和打包临时副本统一位于 `apps.noindex/`，`dist/` 根目录用于 DMG 等交付文件。不要直接打开这些构建副本，以减少系统中同名 App 的重复入口；安装后只从 `~/Applications` 启动：

```sh
open "$HOME/Applications/Keynest.app"
```

`install-apps.sh` 仅安装本项目的两个 App。它核对源与目标的 bundle ID、执行文件和签名，拒绝符号链接，并要求先关闭正在运行的旧 App。每份旧 App 会先使用 `ditto` 归档到 `.build/app-backups/时间-UUID.zip`，经压缩包检查、解压、签名和内容对比后才替换；失败时尝试回滚。备份只保存 App 本身，不含密钥库。脚本不自动启动 App、不改系统索引设置、不操作 Dock，也不清理其他旧副本。

本机仅安装 Command Line Tools，缺少 XCTest，直接运行 `swift test` 无法完成。`run-checks.sh` 使用独立 Swift 断言运行器执行 `Tests/KeynestCoreTests/` 中的原有测试方法，不改写断言与测试体，也不访问正式密钥库或真实服务商账号。运行器先验证失败断言确实产生非零退出码，再执行全部测试。0.8.1 核心逻辑、数据升级、首页分组搜索、构建及 App 实机交互的检查范围与结果统一以 [验证记录](verification.md) 为准。

`run-app-checks.sh` 在一次性 `/private/tmp` 虚构库中对真实 AppModel 和 Core 执行集成检查，涵盖创建、工具关联、检索、保存、锁定与重新解锁，并用替身检查 Touch ID 状态与取消边界；不访问正式库、网络、剪贴板或真实指纹凭据。各版本实际通过的检查与数量记录在上述验证记录中。

仅检查指纹解锁资料的文件保护、不查询传感器或创建 Secure Enclave 密钥，可运行：

```sh
bash scripts/run-biometric-checks.sh --file-only
```

可选的真实 Secure Enclave 后端检查，在支持该硬件且已登录的正常桌面会话中运行：

```sh
bash scripts/run-biometric-checks.sh
```

脚本使用临时目录和虚构解锁资料，结束时清理，不访问正式库，不弹出验证 UI，也不要求实际按指纹。0.6 的 12 条断言已通过，覆盖登记、权限、加密封装、隔离与删除，并确认未认证时系统拒绝私钥操作。它不等于真实指纹成功解锁验收；执行环境限制、证据和尚未完成的硬件验收见 [Touch ID 记录](../research/touch-id-0.6.md)。

如果已安装并选用了包含 XCTest 的完整 Xcode 工具链，也可以在本目录使用标准的 `swift test`。上述离线逻辑验证不等于真实服务商账号联调或独立安全审计。

开发时可以使用独立测试目录，避免动到正式密钥库：

```sh
open -n "$HOME/Applications/Keynest.app" --args --test-data-directory /private/tmp/keynest-manual-test
```

该参数只用于正式 App 的显式隔离测试，不会自动读取真实账户或导入其他应用配置；Demo App 忽略此参数并固定使用自己的目录。测试时使用虚构密钥或专门的测试凭据。

## 源码位置

- `Sources/KeynestApp/`：原生界面、菜单、应用状态、剪贴板与备份交互。
- `Sources/KeynestCore/`：工具与密钥模型、预设、数据迁移、加密文件、存储与官方额度适配器。
- `Tests/KeynestCoreTests/`：核心逻辑、工具关联、迁移、预设切换与额度适配测试。
- `scripts/`、`Resources/`：构建、图标和应用元数据。
